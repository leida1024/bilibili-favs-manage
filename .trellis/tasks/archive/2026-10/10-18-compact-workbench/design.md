# 顶层设计：让列表成为工作台主体

## 产品原则
阅读顺序是选功能 → 找收藏夹 → 选择 → 执行 → 看结果。屏幕空间优先给名称、目标名称、数量、进度和操作结果。标题不重复导航；没有发生的事不占状态区。颜色只表达选中、主操作和结果；白底、细分隔、4px 圆角、系统中文字体，无渐变、大卡片或展示性动效。

## 信息架构
```
收藏夹管理  v2.2.0-dev.1             日志 最小化 关闭
复制收藏夹 | 统计 | 管理
┌────────────────────────┬──────────────┐
│ 当前范围 / 必要的一行说明 │ 操作记录      │
│ 搜索  全选/取消全选  计数 │ 级别 跟随最新 │
│ 来源         目标        │ 时间/级别/内容 │
│ 收藏夹列表（单滚动）     │ 日志独立滚动  │
│                        │ 清空 导出     │
├────────────────────────┤              │
│ 实际状态 + 本任务主操作  │              │
└────────────────────────┴──────────────┘
```
默认 640×600，工作区约 416、日志约 220。根 grid 以内容/页脚占左列，日志横跨右列；收日志后左列扩展，不自动更改手工尺寸。容器低于 580 时单列，日志限高移到底部；低高度下进一步压缩日志，保留列表和动作。标题栏和导航固定，内容滚动、日志滚动分别承担不同阅读目的。

## 三任务统一合同
SelectionToolbar 仅管理 UI：读行模型 `{input,node,name,eligible}`，搜索隐藏不匹配行而不删除节点；全选/取消全选仅作用匹配且合格的行。无匹配时禁用；计数显示全局已选/总数，另标筛选外已选，避免用户看漏执行范围。复制、统计、管理各自拥有实例，统一文案和布局。选择改变交给宿主回调，管理必须先 invalidate 票据。搜索本身不改变选择/票据，不发网络请求。每次目录重置同步工具栏，忙碌时禁用所有编辑。

主列表只显示名称、条数、不可选原因；复选框可访问名称及名称 title 包含 ID/所有者用于同名辨认。执行前预览始终直接显示完整身份及风险；这一步是安全边界，不能为压缩而删除。复制目标输入始终与来源同行，完整名称允许换行，不强制省略。

## 状态与兼容
操作仍由 OperationState/服务/BatchOperations 驱动。保留票据 consume-before-execute、重新校验、停止不重试、独立选择和目录重置。导航无 I/O。忙碌锁定、导出模态焦点和最小化恢复合同不变。侧栏默认打开，收起后的日志继续进入有界 LogStore。功能名称与日志区分别清楚命名。

## 版本合同
运行时 CONFIG.SCRIPT.VERSION 为 2.2.0-dev.1，Rollup 从同一运行时配置取版本，package/lock 同步。回归检查包版本与配置相等；构建后检查 @version。开发版本显示在标题，线上状态仍为 2.1.2。以后每批可交付产品改动递增开发标识，发布是独立动作。

## 设计研究与取舍
按 ui-ux-pro-max 做两次设计系统查询。Minimalism & Swiss Style 与当前工具一致；两次 landing pattern 都偏营销页，不采纳也不持久化其自动输出。采用经过产品语境确认的简约、内容优先、低动效、统一层级原则；保留已验证的蓝色语义 token 和中文系统字体。stack 库没有 vanilla-js，html-tailwind 结果仅采纳语义焦点/溢出规则，不引入 Tailwind。高密度通过减少重复信息和 padding 实现，不缩到 12px 以下。

## 验证与回退
先虚构长短列表和合成破坏操作测试，再浏览器布局/键盘/375px/横屏/低高度验收，最后真实账号只读注入。以完整可见行数和真实布局为证据，不能仅通过无 overflow 声称可用。回退产品提交即可；无持久化迁移。
