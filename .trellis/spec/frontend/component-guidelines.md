# Components and UI

`FloatingPanel` receives a manager instance. `UIComponents` creates DOM elements and `CheckboxItem` models a source/target row; `EventHandlers` coordinates user interaction. There is no component framework or stylesheet build pipeline.

For example, `FloatingPanel.refreshFavorites()` stores checked state and target text before replacing the list. Preserve this behavior across DOM refreshes and route changes. Keep Bilibili operations in the manager/adapters, not visual factories.

Use textContent/value for externally supplied names and log messages. Keep native buttons/inputs usable with keyboard focus and labels. New UI should use panel-scoped styles and avoid changing Bilibili's global page styles. Preserve drag, resize, minimize, and explicit close behavior unless the task deliberately changes them.

UI design work starts in the fictional preview with empty, long-list, busy, error, and narrow-screen examples. A preview must not invoke the real manager's mutation methods. User documentation screenshots must remain synthetic.

Default to the copy task. Keep each source checkbox/name and editable destination alongside one another at desktop and narrow panel widths; use container queries because the window can be resized independently of the viewport. Use a compact content-sized window with a viewport-bounded height; preserve explicit manual dimensions and restore automatic height after minimize when no manual height exists. Keep navigation and action footer outside the single scrolling task body. Lists must not introduce nested scrollbars. Records are a secondary region below the footer with their own bounded scroller and time/level/message columns; opening them never replaces the task. At low viewport heights, the footer/record region can scroll to keep every control reachable.

The user explicitly rejected content expand/collapse controls. Display help, folder IDs/owners and operation details directly. Optional diagnostics are opened with the header's `aria-expanded` button; this does not hide essential operation information. Use horizontal rows and concise text to reduce height. Progress details use persistent footer nodes; updates must not recreate controls, steal focus or force task scrolling. Idle operation content may be absent; active/terminal details must be visible without a click. Destructive confirmation must always expose exact IDs, owners and counts.

`InventoryPanel.resetCatalog(message)` clears report/result/catalog/selection/ticket and stale task scroll on scope changes, explicit reload and mutation completion. Scope change resets operation feedback; completed mutation results remain visible after reset. No stale statistics export may survive a mutation. Failed/cancelled load must replace loading text with recovery guidance. Confirmation hides the redundant preview action; abandoning invalidates the ticket, restores the preview action and focuses it. Records preserve their own scroll when follow is disabled and skip hidden/minimized rerenders. Operation lifecycle transitions are recorded once, not on every progress count. Test these transitions, not just first-open screenshots.

`FloatingPanel.showView(view)` only accepts copy/statistics/manage, performs no I/O and is idempotent for the active view. Actual task switches preserve copy edits, independent statistics/management selections and per-task scroll, while invalidating destructive tickets. `toggleLogs()` changes only diagnostics visibility; it must not call setMode/invalidate or reset task scroll. Busy operation navigation is locked, while records remain accessible. Export review is a modal overlay with inert task/header/footer/navigation/diagnostics, keyboard focus containment, Escape close and focus restoration. Do not append export text below a long task list.

Use scoped `--bf-font`, `--bf-text` (14px), `--bf-small` (12px), `--bf-title` (16px) and semantic color tokens. All labels, form controls, export text and records inherit the local Chinese-friendly system sans stack. Avoid external font loading or a second monospace family. Verify against hostile host form/label font rules and reduced-motion. Essential text pairs need 4.5:1 contrast; visible control boundaries/focus need 3:1. Disabled controls are checked for semantic disabling rather than normal contrast.

Prioritize dynamic lists and outcomes over static help. Copy metadata belongs on the heading row, and help is one concise paragraph. Status/count share a line; specific detail and last-confirmed text flow together below. Do not add a separate generic failure reminder when the specific result already gives the recovery action. Preserve full wrapping text rather than truncating identities or essential consequences. Check actual visible source rows in the failure-plus-records scenario, not only total panel overflow. Reduced-motion selectors must match the specificity of the button/select transition rules; verify computed transition duration is `0s`.
