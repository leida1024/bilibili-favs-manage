# 架构与流程

## 启动

入口为 `src/main.js`。油猴在 `space.bilibili.com/*` 的 `document-start` 阶段注入，等待 DOM 和收藏栏就绪后，实际面板只在 `/{uid}/favlist` 收藏页显示。

1. 创建唯一的 `PageLifecycle`，立即检查页面，此后每 500 毫秒检查一次，并响应 `pageshow`。
2. 检测路由和真实侧栏 DOM。`LegacyPageAdapter.js` 匹配旧版，`VuiPageAdapter.js` 匹配新版。
3. 未找到侧栏则继续等待；15 秒后提示仍未加载或暂不支持，之后仍继续检测。
4. 创建 `FavoriteManager` 与 `FloatingPanel`，绑定日志，立即显示面板。
5. 异步调用 `CrossPageFlowManager.resumeFlow()`；恢复期间阻止面板重复发起任务。

不再等待整个页面的 `load` 事件，也不修改 B 站的 `history`。从空间首页通过站内导航进入收藏页，同样能启动。侧栏列表异步更新时刷新面板，保留勾选与目标名称。同一用户切换收藏夹不重建面板；离开收藏页会卸载面板。

点击销毁后不会被轮询重新打开；用户可通过油猴菜单显式重新显示。

## 页面适配

`core/adapters/index.js` 根据侧栏识别适配器。两个适配文件分别提供列表、批量操作、复制弹窗和分页的选择器，供 `BilibiliAPI` 使用。

- 旧版：从 `#fav-createdList-container` 读取创建列表，排除订阅。
- 新版：从 `.favlist-aside` 中按「我创建的收藏夹」或「TA创建的收藏夹」分组读取，排除后续订阅等分组。

业务层共用切换收藏夹、进入批量模式、全选、打开复制弹窗、选择目标、确认和分页流程。隐藏的预渲染弹窗不会被当成已打开；已全选时再次调用全选不会取消选择。

## 跨页面复制

网页流程通过 DOM 操作；API 流程由独立的 ApiCopyFlow 执行。设置分别选择读取、复制、创建和管理方式。以下为原有网页跨页流程。

```text
他人收藏页：点击开始批量复制
  → 保存 creating 状态、任务列表与 returnURL
  → 跳到自己的收藏页
  → 消费 creating 状态，统一名称、对比自己的目标收藏夹，创建缺失项
  → 保存 copying 状态
  → 返回 returnURL
  → 消费 copying 状态，恢复批量复制，逐个收藏夹、逐页操作
```

自己页面直接进入复制流程。创建收藏夹优先使用侧栏入口；不支持或入口缺失时，尝试从复制弹窗新建。回退方式依赖可进入批量模式的视频列表，空收藏夹可能无法完成创建，可先手动新建目标。

`StateManager` 优先使用 `GM_setValue` / `GM_getValue` / `GM_deleteValue`，不可用时回退到 localStorage。状态有效期为 30 分钟。

恢复创建阶段前检查当前是否为自己的收藏页，恢复复制阶段前检查当前路径是否为原收藏页，避免进入无关用户空间时误恢复任务。

## 名称和创建结果

`utils/favoriteNames.js` 统一处理首尾空白，保留内部空格及连续空格。任务执行前校验整个列表，拒绝空白名称；旧版本持久化的任务在恢复时也使用同样规则。多个源可以复制到同一目标，只有缺失目标的创建列表需要去重。

新建前检查目标是否已经存在，提交后最多等待 5 秒，直到侧栏或复制弹窗列表出现目标才判定成功。弹窗重渲染后重新获取节点。仅侧栏新建入口缺失时使用复制弹窗；已尝试侧栏但结果未确认时停止，避免再次提交。

跨页面状态在实际操作前清除，只有创建全部确认成功后才保存下一阶段。创建或复制失败时停止后续任务；中断后刷新不会自动重放正在执行的阶段，需要先检查实际结果再手动重试。

## 工作区与诊断归属

复制、统计、管理各有一份 OperationState，底部只投影当前功能的状态。目录由统计和管理显式共享，选择互相独立；换范围、重载和管理操作后，目录与旧报告失效。列表读取完成仅写记录，不留下永久的成功状态。

FavoriteManager 持有有界 LogStore；入口在面板挂载前接入同一记录源，面板订阅操作状态、按功能过滤记录。每条诊断包含稳定事件 ID、ISO 时间、级别、功能、任务 ID、阶段和脱敏文本；界面转换为本地时间。跨页状态在交接时保存当前任务的诊断快照，到预期页面合并去重，同一任务保持 ID。日志恢复不会恢复执行队列；执行状态仍在操作前消费。连续诊断保存为当前标签页、当前账号独立的 sessionStorage 快照，刷新后恢复；清空时间戳防止旧交接快照恢复已清空的记录。持久化的只有诊断和界面偏好，不能执行操作。

复制提交只接受新观察到的成功提示为确认，最多等待 6 秒，已有提示不算当前结果。未取得确认归为待核对，显示具体步骤与页码并停止后续任务；入口保留业务层结果，不重复拼接失败/重试文案。创建目标未确认也停止，避免重复创建。


## 独立操作适配层（2.2.2）

- FolderClient：HTTP 列表、统计、创建、复制、删除及退订。type11 是收藏夹，type21 是合集；合集使用独立内容/退订接口。合集内容接口返回完整列表，不能按普通收藏夹20条分页推算。
- WebFolderClient 与 adapters/nativeControls：网页展开、路由身份读取、视频分页和原生菜单操作。自身不直接发 HTTP；同名条目依次核对路由 ID。失效条目不暴露可核对的网页 ID，因此提示选择 API 管理，不能仅按同名条目匹配。
- TransportClient.capture：在确认/扫描开始时固定读写适配器；BatchOperations 继续负责一次性票据、每项重读和停止规则。网页读取/API写入组合也会重新检查当前目标元数据。
- ApiCopyFlow：先完整读取来源快照，再按所选创建方式准备目标，之后逐批 API 复制。不与 DOM 复制混写，也不在失败后换方式。恢复的旧跨页任务明确保留 DOM 流程。
- preferences / PanelLayout：校验后的本地界面偏好；sessionStorage 诊断按账号隔离，localStorage 保存尺寸、位置、记录展开和模式。设置作为第四个普通面板，保留拖动和缩放。记录栏采用固定辅助宽度；收起删除该辅助空间，不让任务区域扩张。

两种路径共用结构化结果 confirmed/failed/unknown/not_started，但各自负责确认平台结果。原生菜单可能直接提交，点击前即视为可能产生效果；后续无法确认则停止且不重试。没有持久化 API 写队列或管理票据。

退订校验与内容可读性分开：完整当前账号订阅列表中的稳定 ID、已知类型和订阅关系足以定位退订；失效合集所有者可能为0，界面保留为未知。已知自己所有、身份冲突或无订阅证据仍拒绝。删除继续要求所有者、可用性与保护状态均确认。统计不将失效内容当作可读取对象。
